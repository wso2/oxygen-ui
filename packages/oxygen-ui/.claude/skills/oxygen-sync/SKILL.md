# Sync the AI documentation with the source code

For maintainers working in the `oxygen-ui` repository. Most of the AI documentation is generated, so this skill runs the generator and coverage check, and reviews what is still written by hand.

## What is generated

## Oxygen UI rules

Follow these rules (version 0.0.1) in all code you write or change. The Oxygen UI analyzer checks them. `.claude/oxygen-ui/rules.md` has how to fix each one, with examples.

- **Import MUI components from Oxygen UI** (`no-direct-mui-imports`, mandatory): Import MUI components, styles and MUI X namespaces from `@wso2/oxygen-ui`, not from `@mui/*` packages.

## Steps

1. Run the coverage check. It reads the library's API from its TypeScript source, so the library does not need building first:

   ```bash
   pnpm rules:coverage
   ```

2. Fix what the coverage check reports. It names the file and the command for each problem:
   - New exports, packages or guides need catalog entries: `pnpm rules:new --component <Name>`, `--package <name>` or `--guide "<Title>"`.
   - A stale API snapshot lists the changed props. Check whether rules or hand-written guides need updating for them.
   - Unknown imports in the hand-written docs need their examples updated.

3. Regenerate the generated files:

   ```bash
   pnpm rules:generate
   ```

4. Review the hand-written guides, `packages/oxygen-ui/.claude/patterns.md`, `theming.md` and `migration.md`, and the skills, for the changed APIs. The coverage check only verifies that imported names exist; check that props and usage match the generated `components.md`.

5. Run `pnpm rules:coverage` again, and report the files that changed and anything that needs a human decision.

## Rules

- Never edit generated files or the generated blocks in skills. Change the rules, the catalog or the template, then regenerate.
- Never modify source code under `packages/oxygen-ui/src`.
- Add a changeset for `@wso2/oxygen-ui` when the shipped AI documentation changes.
